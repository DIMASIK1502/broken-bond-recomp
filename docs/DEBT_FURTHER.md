# Дальняя работа — свой хост-рендер и кадры выше гостевого тика

Это не порт кода из [naruto-rise-recomp](https://github.com/jorjbarbosa/naruto-rise-recomp).
Rise лежит только в `.references/naruto-rise-recomp` (GPL-3.0). Оттуда можно
смотреть *какие проблемы у Jade на 360 бывают*. Файлы, хуки, шейдеры, интерполяцию
и лаунчер Rise **не копировать**.

Наш путь: ReXGlue (BSD), публичные идеи Xenia / Unleashed Recompiled, и разбор
**The Broken Bond** (дамп, логи, `generated/`). Всё, что попадёт в `src/`, пишется
здесь с нуля.

## Зачем это вообще

Сейчас картинку рисует плагин **Xenos**: гостевые command buffer Xbox 360 GPU.
Логика Jade идёт фиксированными шагами (у Rise это 30 в мире / 60 в бою; у BB
цифры надо замерить F1/логами, не гадать). Хост может показывать больше кадров,
только если **не** крутить гостевой тик быстрее — иначе физика и катсцены поедут.

Цель дальнего этапа:

1. Перехватывать гостевой Direct3D (device / resources / draw / present), а не
   исполнять Xenos CB.
2. Переводить шейдеры BB заранее (свой пайплайн на базе публичного XenosRecomp
   или своего транслятора), кэш собирать у нас из `xeshader.sdb` дампа BB.
3. Present 60/120 при том же гостевом шаге: интерполяция камеры, матриц объектов
   и скинов **между двумя последними тиками**, которые мы сами снимем с памяти BB.

Пока этого нет, остаёмся на Xenos + ROV.

## Почему нельзя «перенести Rise»

- Адреса, vtable, константы проекции, список пайплайнов — другие.
- Натив BB — **1280×512 4×MSAA**, не 16:9 Rise. Present и EDRAM-алиасинг другие.
- Их `app/src/gpu/` и патчи SDK — GPL. Даже «переписать похоже, глядя в файл»
  рискованно. Смотрим README/architecture, закрываем их исходники, пишем своё.

## Фазы (по порядку, каждая должна быть играбельной)

### F1. Замер гостевого тика BB

- [x] Лог интервала гостевого `XE_SWAP` (`guest present 5s` в `logs/`).
- [x] Бут, пауза до аттракта и ~25 с после отказа `AttractMode_US.bik`:
      всё те же **30 Гц** (окно, vsync, scale 1). Это не 24 Гц Bink и не 60.
- [x] Бой (`guest-present-012-callers.log`, игрок в бою с ~19:46): **60 Гц**,
      ~300 present за 5 с, все через `sub_821610F0`. Другие три вызова `VdSwap`
      за весь прогон нули.
- [ ] Мир и катсцена отдельно не названы. В том же прогоне после ~15 с бута
      (30 Гц) и до боя всё тоже 60 Гц и тот же `821610F0`. Строка Орочимару
      в прогоне 011 была 30 Гц.

### F2. Карта гостевого D3D

- [x] Импорты графики — не `IDirect3D` / `D3DDevice`. XEX зовёт ядро `Vd*`
      (кольцо, `VdSwap` `0x82C0A9BC`, EDRAM retrain). Список в `PORTING_LOG.md`.
- [x] Единственный вызов `VdSwap` — `sub_821B1DD0`. Его зовут `sub_821B8740`,
      `sub_821A15B0`, `sub_821B2578`, `sub_821610F0`.
- [x] Пакеты лежат в образе, не в импортах. Draw — `DRAW_INDX_2` (`0x36`):
      `sub_821A1348` выбирает `sub_821A0E70` / `sub_821A0D18`, их зовёт
      `sub_821BDFD8` из `sub_821BEB30`. Сброс кадра — `sub_821AD328`, его
      `sub_821610F0` зовёт прямо перед `VdSwap`. Константы — `sub_821BD3D0`
      (`SET_CONSTANT`). Шейдер — `sub_8257A2A0` / `sub_8257A480`
      (`SET_STATE` + `IM_LOAD`), прямого вызова нет. Хуки на них не ставить:
      Xenos по-прежнему рисует.

### F3. Свой backend

- Один Vulkan путь в `src/gfx/`, без Plume из Rise.
- Текстуры/тайлинг Xenos: опираться на SDK/Xenia, не на их `textures/`.
  `Untile` и `GetTiledOffset2D` сходятся на всех 61 форматах, у которых
  блок — степень двойки (1366400 блоков, pitch 32/64/96/128, целиком и
  окном). Пропущены два 1-битных и `k_32_32_32_FLOAT` (12 байт, не тайлится).
  Обратный проход 64×48 `k_8_8_8_8` совпал. Перестановка байт
  `kNone`/`k8in16`/`k8in32`/`k16in32` совпала. 3D (`GetTiledOffset3D`,
  отдельного Untile нет): 2457600 блоков, байт на блок 1..16, pitch
  32/64/96/128, высота 32/64, глубина 16. Адреса в объёме не повторяются,
  шаг Z на 8 слоёв и Y на 32 ряда постоянный, угол тайла по X совпадает
  с формулой SDK. Верхняя граница покрывает каждый блок. 197664 блока
  лежат ниже адреса угла своего тайла, максимум на 2176 байт. Span от
  угла не вместил 6 тайлов. `GetTiledAddressLowerBound3D` маскирует Z
  через `~4`, не `~3`: на 300 углах из 600 (Z = 4 и 12) она указывает
  на предыдущие 4 слоя и ни разу не оказывается выше самого текселя.
- Шейдеры: tool-target `shader_db` (`tools/shader_db.cpp`), вход —
  `game/xeshader.sdb` этого дампа. Опись: 85 исходников и 8156 шейдеров
  (4648 `vs_3_0`, 3508 `ps_3_0`). Микрокод Xenos внутри объекта найден,
  control flow всех 8156 шейдеров сходится (4339980 байт). Таблица констант
  D3DX на смещении `0x28`: 70214 привязки (61033 float4, 9181 sampler),
  127 имён. Установленный `rexgpu-xenos` собран с `REXGLUE_USE_VULKAN=OFF`,
  поэтому утилита компилирует переводчик SPIR-V из соседнего дерева SDK и
  гоняет его в памяти под возможности этой GPU: 8156 из 8156 дают модуль
  SPIR-V 1.5 (319527540 байт),
  у каждого одна точка входа своей стадии. Set 0 binding 0 — shared memory
  у всех, EDRAM-буфера нет. Set 1: system, bool/loop и fetch у всех,
  float-константы у 8138 (максимум 256). Текстуры у 271 вершинного шейдера
  (ровно 2 image + 1 sampler, set 2) и у 3444 пиксельных (set 3, до 16 image
  и 8 sampler). Depth пишут 3, memexport eM — ни один. Файл кэша не пишется.
  Проба этой машины: NVIDIA GeForce RTX 4070, Vulkan 1.4.341, драйвер
  NVIDIA. `maxStorageBufferRange` — 4 ГБ. Перевод включает preserve и RTE,
  sample rate и demote; denorm flush-to-zero выключен, этой возможности
  нет. Scalar block layout и standard layout есть. Драйвер принял все
  8156 `vkCreateShaderModule`. `spirv-val` для Vulkan 1.2 с scalar block
  layout, как у Vulkan-устройства SDK, пропустил все 8156. Графический
  пайплайн с пустым fragment stage собрался для всех 4648 вершинных
  шейдеров. Пиксельные собрались все 3508: у каждого свой set 3 (N image,
  затем M sampler; 9 разных layout), вершинная стадия пишет только
  `gl_Position`, color attachment — по маске render target, depth — у трёх
  шейдеров, которые его пишут. Маска интерполяторов в этой пробе нулевая,
  поэтому входы пиксельного шейдера ещё не стыкуются с выходами вершинного.
  Это ещё не путь `src/gfx/`. Артефакт кэша не коммитить
  (как `generated/`).

### F4. Кадры между тиками

- Два снимка гостевых трансформов на границе тика.
- α = время хоста внутри шага.
- Не ускорять guest clock. Миникарта/HUD могут остаться на тике — это ок.
- Если хост не успевает — падать на частоту тика, не в слоумо.

### F5. Совместимость с тем, что уже работает

- ROV / чёрный бой: нативный путь не должен снова терять EDRAM-алиасы.
- XMA: кадр на границе пакета не добивать нулями. Первую половину держать до
  реального второго буфера (см. `PORTING_LOG.md`, прогон 011).
- Occlusion queries: не подставлять фейковые sample count (катсцены встанут).
- Переключатель в лаунчере: `renderer = xenos | host` (host только когда F3 жив).

## Явно не входит в эту папку долга

Мелочи и среднее — в `DEBT_SMALL.md` и `DEBT_MEDIUM.md`.
Инсталлятор / ISO / семь языков лаунчера — среднее, не этот файл.

## Критерий «готово»

Проход сюжета + бой + JP/EN катсцены на `renderer=host` при 60 present и том же
игровом времени, что на Xenos. Пока этого нет — дефолт Xenos.
