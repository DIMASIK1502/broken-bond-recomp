# Карта D3D в Broken Bond (фаза 2)

Что игра делает с графикой на уровне API XDK D3D: функции, их сигнатуры, частота
вызовов и раскладка устройства. Это вход для теневого режима (фаза 3, см.
`HOST_RENDERER.md`). Адреса — этого дампа (`default.xex` из `game/`), найдены по
нашему `generated/` и прогонам. Исходники других портов не использовались.

## Как получено

- `tools/ppc_xref.py` — перекрёстные ссылки по `generated/default`: codegen
  оставляет каждую инструкцию PowerPC комментарием, из них строятся граф `bl`,
  обращения к полям `r3` и список функций библиотеки, которые зовёт код снаружи
  (`entries`). Индекс кэшируется в `out/ppc_xref.pickle`.
- `--d3d_census` (`src/host/d3d_census.cpp`) — хук на 138 функциях-кандидатах:
  счёт вызовов раз в 5 с в логе, первые три набора `r3..r10`, `lr` и `r3` после
  возврата. Плюс разовый дамп двух таблиц состояний из памяти гостя.
- `tools/d3d_map.py` — таблица тени регистров и `D3D_STATES.md` (поля, которые
  пишет каждый сеттер, с именами битов из `registers.h` SDK).

Прогон: бут, аттракт и титульный экран, Vulkan `fbo`, 70 с
(`logs/census-001.log`). Частоты ниже — последнее окно 5 с на титуле: 150
present, 30 Гц. Бой, мир и катсцены ещё не переписывались.

## Где что лежит

- D3D XDK: `0x8219C358`–`0x821BFxxx`. Ниже `0x8219C` — классы движка (например
  `82175CB0` — конструктор, не диспетчер состояний). `0x821A9F20`–`0x821AB668`
  зовёт только код `0x8241…`–`0x824D…` (2–18 вызовов за бут): похоже на XGraphics /
  загрузчик эффектов, в этот документ не входит.
- Рендер-слой движка, который зовёт D3D: `0x8215…`–`0x8217…` и
  `0x825FA…`–`0x825FC…`.
- Устройство в этом прогоне: `0x40001E80`. Present боя берёт его из объекта
  рендера `0x833E378C` (+16), см. `PORTING_LOG.md`.

## API

`r3` везде — устройство, если не сказано иное. «Кадр» — частота на титуле.
Уверенность: **да** — подтверждено полями device и аргументами из прогона;
**вероятно** — по аргументам и соседству; **?** — назначение не установлено.

## Inline-вызовы

Часть API XDK встраивается в код игры. Поля device пишут напрямую и функции
движка, не только D3D: например, `82165FE8` и `821661C8` кладут индексный буфер
в `+12436`, `82166478` — цель в `+12440`; `SetRenderState` — это вызов через
`device+64+4*i`. Обращения к полям `r3` в диапазоне +10000…+13600 нашлись у 22
функций движка вне D3D. Поэтому хук только на функции API увидит не всё.

Вывод для фазы 3: состояние draw брать из тени и полей объектов в момент
`821AE9C0` / `821AE5D0` (до того, как оригинал сбросит грязь), а хуки на
Set*/Create* использовать для учёта ресурсов и сверки.

- Имена `821AE158`, `821B1860`, `821B2958`, `821B2CF0`, `821A0818`,
  `8219DE98`/`DF80`/`E070`, `821AF240`/`821AF4C8`.
- Какие из `821A5C98`/`821A5D90` и `821A59B0`/`821A59E8` создают шейдер, а какие
  только заполняют заголовок.
- Поля сеттеров sampler state (пишут через вычисляемый адрес).
- Бой, мир, катсцены: перепись только бута и титула.
