# Браузерный порт Broken Bond

Локальный запуск Naruto: The Broken Bond в браузере. Модуль Wasm исполняет уже
перекомпилированный гостевой код, рисует через существующий native renderer на
Plume, играет звук и читает клавиатуру и геймпад. Файлы игры выбираются с диска
один раз и остаются в хранилище браузера. Сборка для Windows не меняет ни
рендер, ни runtime.

## Зачем так

ПК-версия уже рисует через `src/render/renderer.cpp` и Plume (Vulkan, SPIR-V,
адреса буферов). Этот путь работает. Браузеру нужен другой backend того же
интерфейса и другой runtime гостевой памяти: у Wasm одна линейная память, нет
aliasing страниц и нет buffer device address.

Готовые куски берутся из трёх референсов, без переноса их игрового кода:

- Trials HD Recompiled: отдельный CMake, который native-пресеты не читают;
  исходники SDK списком, а не через его desktop CMake; Memory64, pthreads,
  WasmFS/OPFS, страница с локальным импортом, кольцо звука, блок ввода.
- LibertyRecomp-web-test: toolchain, флаги `-sMEMORY64 -pthread
  -fwasm-exceptions -msimd128` до подключения Emscripten, `PROXY_TO_PTHREAD`,
  mimalloc на игровой сборке.
- plume-web: WebGPU-backend Plume (`CreateWebGPUInterface`, canvas как
  CSS-селектор, шейдеры WGSL). Это отдельное дерево, не замена
  `thirdparty/plume`.

## Цели

- Страница на localhost открывает игру с графикой, звуком и управлением.
- Игра и сохранения лежат в браузере. Сеть не нужна после импорта.
- `win-amd64-*` собирает тот же native renderer, что и сейчас.

## Не цели

- Стриминг кадров или подкачка файлов игры с сервера.
- Публикация `.wasm`: в нём перекомпилированный код игры.
- Замена Xenos на ПК и правка Vulkan-пути Plume.
- Патч Trials целиком: он меняет Vulkan и codegen под другую игру.

## Ограничения

- Native Plume остаётся commit `0ce184b`. WebGPU — `thirdparty/plume-web`
  commit `73a662579698c8eb954e0697220a8817cdc64472`, только при
  `BROKEN_BOND_WEB=ON`.
- ReXGlue на ПК остаётся `v0.10.0` с текущими патчами. В этом теге нет
  Emscripten-файлов. Веб-платформа SDK — отдельный узкий патч (платформа,
  память, потоки, аудио, ввод), не патч Trials.
- Гостевое окно — 2.75 ГиБ (`0xB0000000`), как у ReXGlue. Вид `0xE0000000`
  попадает в физическую память со сдвигом `0x1000`, как уже считает native
  renderer.
- Шейдеры ПК остаются SPIR-V с `vk::RawBufferLoad` по адресу буфера.
  WebGPU такие адреса не даёт (`getDeviceAddress` в plume-web — assert) и
  принимает WGSL. Веб-кэш — второй контракт: то же upload-кольцо как storage
  buffer, в push constants смещения, не GPU-адреса. `xenos_shader_common.h`
  для `__spirv__` не меняется.
- Память игрового модуля: `-sMEMORY64=1`, начальные 3328 МБ, потолок 8 ГБ,
  пул из 48 pthread. Оболочка страницы, пока игра не слинкована, держит
  256 МБ, чтобы её можно было открыть без резерва гостевого окна.
- Сервер только `127.0.0.1`, с COOP/COEP. Без этих заголовков нет
  SharedArrayBuffer.

## Как это собирается

`BROKEN_BOND_WEB=OFF` по умолчанию. Включённый флаг под toolchain Emscripten
подключает `cmake/web/broken_bond_web.cmake` и делает `return()` до
`generated/rexglue.cmake`. Desktop-список целей тот файл не видит.

Порядок, в котором порт становится игрой:

1. Страница, локальный импорт папки с `default.xex` в OPFS, блок ввода,
   кольцо звука. Модуль ещё без гостевого кода.
2. Узкий веб-патч SDK и линковка `generated/default` (его даёт native-сборка).
3. `Renderer::Open` на вебе зовёт `CreateWebGPUInterface` и вешает swapchain
   на `#canvas`. Пока кэш WGSL не собран, Open останавливается с явной
   причиной и не кормит backend байтами SPIR-V.
4. Веб-кэш шейдеров и смещения вместо адресов. Дальше работает уже
   существующий разбор draw, текстур и present.
5. Драйвер звука SDK пишет в то же кольцо, которое читает AudioWorklet.
   Драйвер ввода читает тот же блок, который пишет страница.

## Критерий готовности

На localhost, после выбора своей папки `game/`, меню, сюжет и бой идут
картинкой и звуком с клавиатуры или стандартного геймпада. Та же рабочая
копия репозитория по-прежнему собирает `broken_bond.exe` пресетом
`win-amd64-relwithdebinfo`.
